👨‍💻 Инкапсуляция — MODULE_06_PART3

Зачем это нужно?

Инкапсуляция — это как сейф: внутри ценности (данные), снаружи замок (методы). Прячем поля класса с private, даём доступ только через getters (чтение) и setters (запись с проверками).

Правило: Никогда не делай поля public! Всегда private + getter/setter.

Шаблон класса с инкапсуляцией

public class Product {
    // 1. Поля PRIVATE
    private String name;
    private double price;
    private int stock;
    
    // 2. GETTERS (только чтение)
    public String getName() {
        return name;
    }
    
    public double getPrice() {
        return price;
    }
    
    // 3. SETTERS (запись + ВАЛИДАЦИЯ)
    public void setName(String name) {
        if (name == null || name.trim().isEmpty()) {
            throw new IllegalArgumentException("Имя товара не может быть пустым!");
        }
        this.name = name.trim();  // this отличает поле от параметра
    }
    
    public void setPrice(double price) {
        if (price < 0) {
            throw new IllegalArgumentException("Цена не может быть отрицательной!");
        }
        this.price = price;
    }
    
    // 4. Бизнес-методы (работают с private полями)
    public double getDiscountPrice() {
        return price * 0.9;  // скидка 10%
    }
    
    public boolean isInStock() {
        return stock > 0;
    }
}

Ключевые отличия

Без инкапсуляции (ПЛОХО)С инкапсуляцией (ХОРОШО)
public String name;  // любой может испортить
product.name = null;  // сломал объект
 
private String name;
product.setName("");  // setter проверит и откажет
 
public double price;
product.price = -100; // отрицательная цена?!
 
product.setPrice(-100);  // выбросит ошибку

Важные правила

  • this.name = name; — this отличает поле класса от параметра метода
  • Getter: public Тип getИмя() { return поле; }
  • Setter: public void setИмя(Тип имя) { проверки; this.поле = имя; }
  • Валидация в setter — защита от "дурных" данных
  • Можно иметь только getter (только чтение) или только setter (редко)
