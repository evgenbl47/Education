Принцип Инкапсуляции

Инкапсуляция — это механизм скрытия внутренних деталей реализации объекта и защиты его состояния от прямого вмешательства извне. Мы объединяем данные (поля) и методы для работы с ними в одном классе.

1. Зачем это нужно?

  • Безопасность: Никто не сможет записать в переменную age значение -500.
  • Гибкость: Ты можешь изменить внутреннюю логику хранения данных, не ломая код, который использует твой класс.
  • Скрытие сложности: Пользователь класса видит только простые методы (кнопки), а не весь "двигатель" внутри.

2. Реализация: private + методы

Мы закрываем доступ к полям с помощью модификатора private и открываем "форточки" для доступа через Getter (чтение) и Setter (запись).

public class BankAccount {
    // Поле скрыто! Никто не украдет деньги напрямую
    private double balance;

    // Геттер: позволяем посмотреть баланс
    public double getBalance() {
        return balance;
    }

    // Сеттер: позволяем положить деньги, но только если сумма положительная
    public void deposit(double amount) {
        if (amount > 0) {
            this.balance += amount;
            System.out.println("Пополнено на: " + amount);
        } else {
            System.out.println("Ошибка: сумма должна быть больше 0");
        }
    }
}

3. Ключевое слово this

В сеттерах мы часто используем this.fieldName = fieldName;. Слово this указывает Java, что мы обращаемся именно к полю класса, а не к локальному параметру метода с таким же именем.
