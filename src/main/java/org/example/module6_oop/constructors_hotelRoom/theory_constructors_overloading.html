🔧 Constructor Overloading (Перегрузка конструкторов)

Модуль: Module 6: OOP — Part 2

Тема: Гибкая инициализация объектов

🧠 Что это такое?

Перегрузка конструкторов — это когда в классе есть несколько конструкторов с разными параметрами.

💡 Аналогия: Заказ пиццы 🍕
• Полная: тесто + соус + сыр + начинка
• Базовая: тесто + соус (начинка по умолчанию)
• По умолчанию: стандартная пицца без параметров
И то, и то — пицца! Просто разная комплектация.

💻 Пример кода

public class Pizza { String dough; String sauce; String topping; // 🔥 Конструктор 1: Полная пицца public Pizza(String dough, String sauce, String topping) { this.dough = dough; this.sauce = sauce; this.topping = topping; } // 🔥 Конструктор 2: Базовая (без начинки) public Pizza(String dough, String sauce) { this(dough, sauce, "No topping"); // Вызов конструктора 1 } // 🔥 Конструктор 3: По умолчанию public Pizza() { this("Standard", "Tomato", "Cheese"); // Вызов конструктора 1 } }

📋 Как Java выбирает конструктор?

Вызов Какой конструктор сработает
new Pizza("Thin", "Tomato", "Pepperoni") Конструктор с 3 параметрами
new Pizza("Thin", "Tomato") Конструктор с 2 параметрами
new Pizza() Конструктор без параметров
⚠️ Важно: Конструкторы должны отличаться количеством или типом параметров!

🔗 Зачем это в Full-stack?

Сценарий Пример
Гибкость Клиент создаёт объект с полными или минимальными данными
Значения по умолчанию Если параметр не передан — используется дефолтное значение
Обратная совместимость Можно добавить новый конструктор, не ломая старый код

🔑 Ключевые правила

  • this(...) вызывает другой конструктор этого же класса
  • this(...) должен быть первой строкой в конструкторе
  • Не путай: this(...) = вызов конструктора, this.field = поле объекта
  • Если не написать ни одного конструктора — Java создаст конструктор по умолчанию
  • Если написал конструктор с параметрами — по умолчанию не создаётся
💡 Совет: Используй this(...), чтобы не дублировать код инициализации. Все конструкторы → одна логика → легче поддерживать!
