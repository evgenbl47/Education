🔐 Encapsulation (Инкапсуляция)

Модуль: Module 6: OOP — Part 3

Задача: encapsulation_userAuth_private

Тема: Защита данных через private поля и public методы

🧠 Что такое инкапсуляция?

Инкапсуляция — это механизм скрытия внутренних данных класса и предоставления контролируемого доступа к ним через методы.

💡 Аналогия: Банкомат 🏦
• Без инкапсуляции: Любой может открыть заднюю панель и забрать деньги
• С инкапсуляцией: Доступ только через защищённый интерфейс (карта + PIN)
Внутри — сложные процессы, снаружи — простой и безопасный интерфейс.

🔑 Модификаторы доступа

Модификатор Видимость Когда использовать
private Только внутри класса Поля и внутренние методы (скрыть данные)
public Везде Методы для внешнего доступа (API класса)
protected В пакете + наследники Для наследования (изучим позже)
(default) Только в пакете Когда нет модификатора

💻 Пример: БЕЗ инкапсуляции (проблема)

public class User { String username; // ← public (по умолчанию) String password; // ← Любой может изменить! int age; } // В другом классе: User user = new User(); user.password = "123"; // 😱 Пароль изменён без проверки! user.age = -50; // 😱 Отрицательный возраст!
⚠️ Проблема: Поля доступны всем → данные можно испортить случайно или намеренно!

💻 Пример: С инкапсуляцией (решение)

public class User { private String username; private String password; private int age; // 🔥 Геттер (getter) — чтение public String getPassword() { return password; } // 🔥 Сеттер (setter) — запись с проверкой public void setPassword(String password) { if (password.length() >= 8) { this.password = password; } else { System.out.println("Error: Password must be 8+ characters!"); } } // 🔥 Сеттер с валидацией возраста public void setAge(int age) { if (age >= 0 && age <= 150) { this.age = age; } else { System.out.println("Error: Invalid age!"); } } }

📋 Геттеры и Сеттеры

Метод Назначение Возвращает Пример
Getter Чтение значения поля Тип поля getPassword()
Setter Запись значения с проверкой void setPassword(String pwd)
💡 Совет: Именование геттеров/сеттеров:
• Геттер: get + ИмяПоля с заглавной → getUsername()
• Сеттер: set + ИмяПоля с заглавной → setUsername(String name)
• Для boolean: isActive() или getActive()

🔗 Зачем это в Full-stack?

Сценарий Пример
Безопасность Пароли, токены, личные данные скрыты от прямого доступа
Валидация Проверка данных перед записью (возраст, email, цена)
Гибкость Можно изменить внутреннюю логику, не ломая внешний код
DTO/Entity Модели данных в Spring/Hibernate используют геттеры/сеттеры

🔑 Ключевые правила

  • Поля класса должны быть private (скрыты от внешнего мира)
  • Для доступа к полям используй public геттеры и сеттеры
  • В сеттерах добавляй валидацию данных (проверки)
  • Геттеры только читают данные (не меняют состояние)
  • Если поле не должно меняться — не создавай сеттер (только геттер)
💡 Совет: В IntelliJ IDEA: Code → Generate → Getter and Setter (Alt+Insert) создаст их автоматически!
