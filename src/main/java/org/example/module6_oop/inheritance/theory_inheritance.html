🧬 Inheritance (Наследование)

Модуль: Module 6: OOP — Part 4

Задача: inheritance_userRoles

Тема: Создание иерархии классов через extends

🧠 Что такое наследование?

Наследование — это механизм, позволяющий одному классу (потомку) наследовать поля и методы другого класса (родителя).

💡 Аналогия: Семья 👨‍👩‍👧‍👦
• Родитель: передаёт детям фамилию, цвет глаз, привычки
• Ребёнок: получает всё от родителя + может иметь свои уникальные черты
• Полиморфизм: один и тот же метод «говорить» работает по-разному у разных людей

📊 Иерархия классов (пример)

                    Object (корень всех классов)
                        │
                        ▼
                    User (родитель)
                   /     |     \
                  ▼      ▼      ▼
              Admin   Guest  Moderator
              (потомки)

🔑 Ключевые слова

Ключевое слово Назначение Пример
extends Наследование от родительского класса class Admin extends User
super Обращение к методам/конструкторам родителя super.username, super(...)
@Override Переопределение метода родителя в потомке @Override public void printInfo()

💻 Пример: Родительский класс

public class User { private String username; private String email; public User(String username, String email) { this.username = username; this.email = email; } public String getUsername() { return username; } public String getEmail() { return email; } public void printInfo() { System.out.println("User: " + username + " (" + email + ")"); } }

💻 Пример: Класс-потомок

public class Admin extends User { private boolean canDeleteUsers; // 🔥 Конструктор потомка public Admin(String username, String email, boolean canDelete) { super(username, email); // Вызов конструктора родителя this.canDeleteUsers = canDelete; } // 🔥 Геттер для нового поля public boolean canDeleteUsers() { return canDeleteUsers; } // 🔥 Переопределение метода родителя @Override public void printInfo() { super.printInfo(); // Вызов метода родителя System.out.println("Role: ADMIN"); System.out.println("Can delete users: " + canDeleteUsers); } // 🔥 Уникальный метод потомка public void deleteUser(User user) { if (canDeleteUsers) { System.out.println("Deleted user: " + user.getUsername()); } } }

📋 Правила наследования

Правило Объяснение
Один родитель Класс может наследовать только от одного класса (но от многих интерфейсов)
private не наследуется Приватные поля/методы родителя не видны в потомке (но существуют!)
super() первым Если в конструкторе потомка есть super(...), он должен быть первой строкой
@Override опционален Аннотация не обязательна, но помогает компилятору найти ошибки
⚠️ Важно: Если у родителя нет конструктора без параметров, потомок обязан явно вызвать super(...)!

🔁 Полиморфизм (базовое понятие)

Полиморфизм — возможность использовать объект потомка там, где ожидается объект родителя.

// ✅ Полиморфизм: Admin «является» User User user1 = new User("guest", "g@example.com"); User user2 = new Admin("admin", "a@example.com", true); // ← Admin как User! user1.printInfo(); // Вызовет User.printInfo() user2.printInfo(); // Вызовет Admin.printInfo() (переопределённый)!
💡 Совет: Полиморфизм позволяет писать гибкий код:
public void register(User u) примет и User, и Admin, и Guest!

🔗 Зачем это в Full-stack?

Сценарий Пример
Роли пользователей User → Admin, Moderator, Guest с разными правами
Типы платежей Payment → CreditCard, PayPal, Crypto
Spring Framework Контроллеры, сервисы, репозитории — всё строится на наследовании
Тестирование Mock-объекты наследуют интерфейсы для подмены зависимостей

🔑 Ключевые правила

  • Используй extends для создания иерархии «является» (Admin is a User)
  • Вызывай super(...) в конструкторе потомка для инициализации полей родителя
  • Используй @Override при переопределении методов — это защита от опечаток
  • Через super.method() можно вызвать оригинальную версию метода родителя
  • Полиморфизм: переменная типа родителя может ссылаться на объект потомка
💡 Совет: В IntelliJ IDEA: Code → Override Methods (Ctrl+O) покажет список методов для переопределения!
