1. Что такое наследование?

Наследование позволяет создать новый класс на основе существующего. Новый класс получает все поля и методы родителя.

    🐕 Animal (Родитель / Superclass)
    /           \
    /             \
    🐕 Dog          🐱 Cat
    (Child)        (Child)

Зачем это нужно?

  • DRY (Don't Repeat Yourself) — не пиши одно и то же в каждом классе
  • Иерархия — логичная структура кода
  • Полиморфизм — работа с разными типами через общую ссылку
// Общий синтаксис:
public class Child extends Parent {
    // Наследует всё от Parent
    // + может иметь свои поля и методы
}
💡 Важно: В Java класс может наследоваться только от одного родителя.

2. Модификатор protected

Для наследования критически важен модификатор protected. Он делает поля видимыми для наследников, но скрытыми от внешнего кода.

Модификатор В классе В пакете В наследнике Везде
private ✅ ❌ ❌ ❌
protected ✅ ✅ ✅ ❌
public ✅ ✅ ✅ ✅ 
public class Animal {
    protected String name;  // 👈 Видно в Dog и Cat
    protected int age;
}

3. Ключевое слово super

super используется для обращения к родителю. Чаще всего — для вызова конструктора.

public class Dog extends Animal {
    public Dog(String name, int age, String breed) {
        super(name, age);  // 👈 ПЕРВАЯ СТРОКА!
        this.breed = breed;
    }
}
⚠️ Правило: super(...) должен быть первой строкой в конструкторе наследника. Иначе компилятор выдаст ошибку.

Почему первая строка?

Логика: «Сначала построй фундамент (родитель), потом возводи стены (наследник)». Нельзя использовать объект, пока он не инициализирован полностью.

4. Переопределение методов (@Override)

Наследник может изменить поведение метода родителя. Для этого используется та же сигнатура (название + параметры).

// В классе Animal:
public void makeSound() {
    System.out.println("Some sound");
}

// В классе Dog:
@Override
public void makeSound() {
    System.out.println("Woof!");  // 👈 Своё поведение
}
💡 @Override — это аннотация-страховка. Если ты ошибёшься в названии метода, компилятор подскажет.

5. Полиморфизм

Полиморфизм — это возможность использовать объект наследника там, где ожидается объект родителя.

Animal myPet = new Dog(...);  // 👈 Ссылка Animal, объект Dog
myPet.makeSound();  // Вызовется версия Dog ("Woof!")

Зачем это нужно?

Ты можешь создать массив общего типа и хранить там разные объекты:

Animal[] pets = new Animal[3];
pets[0] = new Dog(...);
pets[1] = new Cat(...);
pets[2] = new Animal(...);

for (Animal a : pets) {
    a.showInfo();  // Каждый объект покажет свою версию!
}

6. Приведение типов (Casting)

Если у тебя есть ссылка типа родителя, но нужно вызвать метод наследника — требуется приведение типа.

Animal pet = new Dog(...);

// ❌ Не работает:
pet.fetch();  // Ошибка: у Animal нет метода fetch()

// ✅ Работает:
if (pet instanceof Dog) {
    Dog d = (Dog) pet;  // 👈 Приведение
    d.fetch();          // 👈 Теперь доступно!
}

Алгоритм безопасного casting:

  1. Проверь тип: if (obj instanceof Type)
  2. Приведи тип: Type t = (Type) obj;
  3. Вызови метод: t.specificMethod();
⚠️ Без instanceof: Если привести тип неправильно, программа «упадёт» с ClassCastException во время выполнения.

7. Upcasting vs Downcasting

Тип Направление Синтаксис Безопасность
Upcasting Ребёнок → Родитель Animal a = new Dog(); ✅ Автоматически
Downcasting Родитель → Ребёнок Dog d = (Dog) a; ⚠️ Требует instanceof

8. Шпаргалка для практики

✅ Чеклист перед началом кода

  • Придумай поля для базового класса (общие для всех)
  • Придумай уникальные поля для каждого наследника
  • В конструкторах наследников: super(...) первой строкой
  • Переопредели методы с @Override
  • В тесте: массив типа родителя + цикл для полиморфизма
  • Для уникальных методов: instanceof + casting
