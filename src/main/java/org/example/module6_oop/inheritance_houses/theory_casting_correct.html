🔍 Deep Dive: Приведение типов (Casting)

Разбираем подробно: (Cottage) cottage и ((Skyscraper) s).goToFloor()

🎯 Короткий ответ

Приведение типа — это способ сказать компилятору:

«Я знаю, что эта ссылка выглядит как House, но я гарантирую, что внутри лежит Cottage. Пожалуйста, разреши мне использовать методы Cottage».

1. Контекст: Полиморфизм и «потеря» методов

// Создаём объект
House cottage = new Cottage("Forest 5", 120, 2020, true, 300);

// Что видит компилятор?
// 👀 Тип ссылки: House
// 📦 Реальный объект: Cottage

📊 Визуализация переменной

📦 Переменная "cottage"
Тип ссылки: House
Что видит компилятор: Только методы House
Адрес в памяти: → [Cottage]
Что видит JVM: Все методы Cottage
🔎 Ключевая проблема:
  • Компилятор (когда ты пишешь код) проверяет только тип ссылки (House). Он говорит: «У House нет метода plantTree() — ошибка!»
  • JVM (когда программа работает) видит реальный объект (Cottage) и могла бы вызвать метод, но компилятор её не пускает.

2. Решение: Downcasting (приведение вниз)

Чтобы «вернуть» доступ к методам Cottage, нужно явно привести тип.

// Синтаксис: (Тип) переменная
Cottage c = (Cottage) cottage;  // 👈 Приведение типа
c.plantTree();                // 👈 Теперь работает!
🔎 Пошаговый разбор:
  • (Cottage) — оператор приведения. Говорит: «Считай, что это Cottage».
  • cottage — исходная переменная типа House.
  • Cottage c = ... — создаём новую ссылку типа Cottage, которая указывает на тот же объект.
  • Теперь через c компилятор разрешает вызывать plantTree().

3. Два способа записи

🅰️ Вариант 1: С промежуточной переменной (рекомендуется)

if (cottage instanceof Cottage) {
    Cottage c = (Cottage) cottage;  // Создаём "понятную" ссылку
    c.plantTree();                  // Читаемо и безопасно
}

✅ Плюсы: Код легче читать, можно использовать c несколько раз.

🅱️ Вариант 2: Без переменной (коротко)

if (cottage instanceof Cottage) {
    ((Cottage) cottage).plantTree();  // 👈 Двойные скобки!
}
🔎 Почему двойные скобки?
  • Внутренние (Cottage) cottage — приводят тип.
  • Внешние ( ... ).method() — говорят: «вызови метод у результата приведения».
  • Без внешних скобок компилятор подумает, что ты пытаешься привести к типу результат вызова метода — и выдаст ошибку.

4. Аналогия из жизни 🏠

📦 Коробка с ключами

У тебя есть коробка с надписью «Дом» (House).

Внутри лежит ключ от коттеджа (Cottage), который может открыть садовую калитку (plantTree()).

Шаг Действие Код
1️⃣ Проверить: «А точно ли внутри коттедж?» instanceof
2️⃣ Переподписать коробку: «Теперь это Коттедж» (Cottage)
3️⃣ Теперь можно сказать: «Открой калитку!» plantTree()

5. Upcasting vs Downcasting

Тип Направление Синтаксис Безопасность
Upcasting
Вверх по иерархии		 Cottage → House House h = cottage;
(автоматически)		 ✅ Всегда безопасно
Downcasting
Вниз по иерархии		 House → Cottage Cottage c = (Cottage) h;
(явно)		 ⚠️ Требует instanceof

⚠️ Опасность без instanceof

House h = new House(...);  // Внутри НЕ Cottage!
Cottage c = (Cottage) h;  // 💥 ClassCastException при запуске!

Компилятор пропустит, но программа «упадёт» во время выполнения. Всегда проверяй через instanceof!

7. Практическая шпаргалка

✅ Алгоритм безопасного вызова метода наследника

  1. Есть ссылка типа родителя: House h = ...
  2. Хочешь вызвать метод ребёнка: plantTree()
  3. Проверь тип: if (h instanceof Cottage)
  4. Приведи тип: Cottage c = (Cottage) h;
  5. Вызови метод: c.plantTree();
// Пример из твоего кода — теперь с пониманием:
if (cottage instanceof Cottage) {          // 1. Проверка
    Cottage c = (Cottage) cottage;          // 2. Приведение
    c.plantTree();                          // 3. Вызов ✅
}

// Или коротко (вариант со скобками):
if (skyscraper instanceof Skyscraper) {
    ((Skyscraper) skyscraper).goToFloor(5);  // Привели и сразу вызвали
}

8. Частые ошибки

❌ Ошибка 💡 Почему не работает ✅ Как исправить
cottage.plantTree(); Компилятор видит тип House, у которого нет этого метода Привести тип: ((Cottage)cottage).plantTree()
(Cottage cottage).plantTree(); Неверный синтаксис: нельзя объявлять тип внутри скобок приведения Только выражение: (Cottage) cottage
Пропустить instanceof Если объект не того типа — программа «упадёт» с ClassCastException Всегда проверять: if (obj instanceof Type)
