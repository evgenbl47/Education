🏠 Module 6 Part 4: Inheritance & Polymorphism

Версия для задачи inheritance_houses. Вся теория на примере строительства домов.

1. Зачем нужно наследование? (DRY)

Представь, что ты пишешь программу для застройщика. У тебя есть Обычный Дом, Коттедж и Небоскрёб.

У всех них есть общее:

  • Адрес (address)
  • Площадь (square)
  • Год постройки (yearBuilt)

Писать эти поля в каждом классе три раза — плохо. Это нарушает принцип DRY (Don't Repeat Yourself). Мы вынесем общее в базовый класс House.

🏢 House (Базовый класс) / \ / \ 🏡 Cottage 🏢 Skyscraper (Наследник) (Наследник)

2. Ключевое слово extends

Чтобы сказать Java, что класс наследуется, используем extends.

public class House {
    protected String address;  // protected: видно в классе и наследникам
    protected int square;

    public House(String address, int square) {
        this.address = address;
        this.square = square;
    }
}

public class Cottage extends House {  // 👈 Наследование
    private int gardenSize;

    public Cottage(String address, int square, int gardenSize) {
        // Конструктор будет ниже...
    }
}
⚠️ Важно: В Java класс может наследоваться только от одного родителя.
class Cottage extends House, Building — ❌ Ошибка!

3. Ключевое слово super

Класс Cottage должен инициализировать поля родителя (address, square). Для этого используется super.

public Cottage(String address, int square, int gardenSize) {
    super(address, square);  // 👈 ПЕРВАЯ СТРОКА! Вызов конструктора House
    this.gardenSize = gardenSize; // 👈 Потом свои поля
}
💡 Правило первой строки: Вызов super(...) должен быть самой первой инструкцией в конструкторе наследника.
Логика: «Сначала построй фундамент (House), потом возводи стены (Cottage)».

4. Переопределение методов (@Override)

У всех домов есть метод showInfo(), но коттедж хочет выводить ещё и размер сада.

// В классе House
public void showInfo() {
    System.out.println("House: " + address);
}

// В классе Cottage
@Override  // 👈 Страховка от опечаток
public void showInfo() {
    // Можно вызвать метод родителя, если нужно:
    super.showInfo();
    System.out.println("Garden: " + gardenSize);
}

5. Полиморфизм

Это возможность использовать объект наследника там, где ожидается объект родителя.

House myHome = new Cottage("Forest 5", 120, 300);
// Ссылка типа House, но объект типа Cottage

myHome.showInfo();
// Вызовется метод Cottage (если он переопределён)! 
// Это называется динамическое связывание.

Зачем это нужно? Ты можешь создать массив домов и хранить там разные типы:

House[] buildings = new House[3];
buildings[0] = new House("Lenina 10", 50);
buildings[1] = new Cottage("Forest 5", 120, 300);
buildings[2] = new Skyscraper("Center 1", 5000, 50);

for (House h : buildings) {
    h.showInfo();  // Каждый объект покажет свою инфо!
}

6. Проверка типа (instanceof)

Иногда нужно узнать конкретный тип объекта, чтобы вызвать его уникальные методы (например, plantTree() есть только у Cottage).

if (myHome instanceof Cottage) {
    // Теперь мы уверены, что это Cottage
    Cottage c = (Cottage) myHome;  // Приведение типа
    c.plantTree();  // Теперь можно вызвать!
}

7. Модификаторы доступа

Для наследования критически важен protected.

Модификатор В классе В пакете В наследнике Везде
private ✅ ❌ ❌ ❌
protected ✅ ✅ ✅ ❌
public ✅ ✅ ✅ ✅

👉 Поля address и square в классе House должны быть protected, чтобы наследники видели их напрямую.
